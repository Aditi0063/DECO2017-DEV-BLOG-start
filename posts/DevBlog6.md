# My last blog - User Testing Plan and Building

## Planning for Evaluation - User Testing 

As our wireframes and databses are finalised, the next step before writing code is to validate whether our interface is sensible to our target audience. We are planning on conducting two simple user testing sessions at different stages of the build. 

### Session 1 - Wireframe walkthrough (5 minutes)

The first session would use our current wireframes as the test material. We will ask our participants (USYD Design students) the seven page sequence and ask them to talk us through what each screen's purpose is and what they could do on the page. The goal is to test the page's functionality and the core flow's legibility. Understanding the user's surface level comprehension gaps will help us change any designs before coding. 

### Session 2 - Static pages with broken links (15 minutes)

The second session uses the first coded version of the application but, only the HTML and CSS with placeholder links between the pages with no databse connections yet. The participants will be required to complete a simple task - find a pitch, apply to join and explore the showcase page. The broken links are intentional to understand and observe where people click to retrack and the navigational structure. 

## Building Plan

The building plan will follow the same logic as the testing plan. HTML and CSS will be built first so that our interface is visually coherant before adding any interactions. HTMX interactions to the apply button, chechklist ticks and fiters. The last step is to connect everything to the SQLdata and the BlaBla Corp login template. This way we can test out and fish any bugs and make sure we don't have our entire system collapse during development.
